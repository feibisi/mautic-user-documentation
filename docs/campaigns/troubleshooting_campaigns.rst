营销活动故障排除
#########################

.. vale on

页面访问未被识别
*****************************

要解决此问题，请尝试以下选项之一：

#. 确保未在登录 Mautic 的情况下测试页面访问。Mautic 会忽略 Mautic 管理员的操作。因此，建议您使用匿名会话、无痕窗口、其他浏览器或退出 Mautic。

#. 确保被跟踪的联系人正在该营销活动中。测试的简便方法是查看联系人的时间线，确认页面访问记录或是否被纳入该营销活动。

#. Mautic 按顺序执行营销活动，并且不会对每个联系人重复执行。如果联系人已在营销活动中访问过页面并触发了"访问页面"判定条件，那么该联系人的后续访问将不会再次触发与该判定条件关联的操作。

#. 确保营销活动操作中的 URL 与访问的 URL 完全匹配，或使用通配符。URL 可包含协议、主机/域名、路径、查询参数和/或片段。例如，如果您的 URL 为 ``https://example.com``，而页面访问记录显示为 ``https://example.com/index.php?foo=bar``，则营销活动判定条件不会触发。但如果您使用 ``https://example.com*`` 作为 URL，则符合匹配规则，因此会被触发。

另一个示例是将不同的页面访问与特定的营销活动关联。例如，您有营销活动 A 和营销活动 B，希望为两个营销活动使用相同的基 URL 和路径，但通过查询参数进行区分。对于营销活动 A，您可以定义"访问页面"判定条件，设置为 ``https://example.com/my-page?utm_campaign=A*``，对于营销活动 B 则设置为 ``https://example.com/my-page?utm_campaign=B*``。这样，联系人只会触发所需的特定营销活动。如果目标是不管查询参数如何都触发两个营销活动，则使用 ``https://example.com/my-page*``。
